THE RUN IS INCOMPLETE, AND THE REASON IS THE MACHINE
----------------------------------------------------
Roughly a third of all checks reported SKIPPED with

    the application exited with exit code: 101 before showing a window

and a stderr containing

    accesskit_windows-0.32.1/src/subclass.rs:109 panicked:
    HRESULT(0x80070008) "Not enough memory resources are available"

That is Windows refusing to create a window's accessibility subclass under
resource pressure. Measured cause:

    OneDrive     349,208 handles
    OUTLOOK       51,751
    explorer      12,206

349k handles in one process is two orders of magnitude past normal. Three
consecutive offscreen launches of pdfce-gui gave 2 successes and 1 crash, and a
slice re-run after a pause went from 1 passed/7 skipped to 6 passed/2 skipped —
so it is pressure, not a hard block, and the suite's back-to-back launches are
what tip it over.

★ NOT a pdfce defect, and worth stating plainly so nobody spends a day on it.
But it IS a crash an operator can hit: pdfce-gui dies at startup with an
accessibility HRESULT that says nothing about the real cause.

THE TWO FAILURES
----------------
1. zooming_does_not_throw_away_where_the_operator_panned — O27's f32 residual,
   pre-existing and filed, deliberately RED.

2. export_dxf_writes_the_pages_geometry — a STALE CHECK, now fixed, and it is
   the interesting one. It reported "the File tab declares no
   `ribbon.item.file.export_dxf`, on the band or in the overflow", which reads
   as a lost command. The command was never lost: S3 gave the band a middle rung
   between "on the band" and "in a menu" — a collapsed group, whose items are
   one click away and publish no rect — and the harness knew about two of the
   three places a command can be. The window the harness opens is 1,100 pt wide,
   which is precisely the width at which the Export group collapses.

   `declared_or_in_overflow` now tries collapsed groups first (non-destructive:
   opening a popup changes nothing about the band, whereas scrolling moves it
   and every rect measured afterwards). The check passes and genuinely exports:
   2,655,575 bytes, 10,076 line entities reported and 10,076 found in the file.
