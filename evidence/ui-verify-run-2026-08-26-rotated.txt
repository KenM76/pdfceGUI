1. blend_space — the harness was wrong, and it has been fixed
--------------------------------------------------------------
Reported: "at zoom 326%, past the 263% at which the renderer refuses the CMYK
compositing buffer, no `status-group:blend-space` line was declared. The page's
colours have changed and nothing on screen says so."

Nothing had changed and nothing was owed. Every `raster-blend-space` line in the
run says `cmyk_buffer=false refused=0 wrong_space=0`, at every scale up to 3.26.

**`SW41177.pdf` has no transparency on it.** It is a SOLIDWORKS drawing set —
line work. A page that never asks for the CMYK compositing buffer never has it
refused, so nothing falls back to sRGB, so there is correctly nothing to
disclose. Everything the check computed before the verdict is arithmetic on the
page's DIMENSIONS, which says the buffer *would* be refused if the page asked
for one.

Re-run against `the conformance suite's composite page at --page-size 596x791`, the
file the check was written for, it PASSES with the disclosure appearing exactly
at the crossing.

★ Left unguarded this was a standing false red on every routine run, because a
CAD drawing is the fixture the operator's suite runs on and the one least likely
to use transparency. A standing false red is worse than no check: it trains a
reader to skip the section. Guarded now — it SKIPs, naming the missing
precondition and naming the fixture that has it. Falsified in both directions:
SKIP on the CAD sheet, PASS on the <the conformance suite> page.
